# Seshat 0.17.0

Release candidate; not yet published. Release preparation and publication are
tracked in [#289](https://github.com/Binary-Balance/seshat/issues/289).

This release removes mutants that test nothing. Arithmetic on string literals
and declaration-only code are no longer mutated, and a setup can now typecheck
each operator mutant so that changes TypeScript would reject stay out of the
score.

## Fewer meaningless mutants

As in Stryker, arithmetic sites with a string or template literal operand are
no longer mutated. `'total: ' + n` would become `NaN`, which any check of the
result kills, so such mutants raised the score without testing anything. The
left operand's right side also counts: `a + 'x' + b` is excluded, but the outer
`+` in `'a' + b + c` is still mutated.

Every operator family now excludes declaration-only code, such as `declare`
blocks and `.d.ts` files, because it emits no JavaScript. Previously the
comparison, logical and arithmetic families could mutate it, for example in a
computed `declare enum` member, producing mutants that could never be killed.

Both exclusions are counted in each operator's `excludedSites`, so projects
that concatenate with `+` or have computed ambient members see fewer planned
mutants, and their scores can shift. No report field changes. See
[mutation operators](../configuration.md#mutation-operators) and the
[real-project check](../research/mutation-operators.md#string-literal-operands).
The change merged in [PR #287](https://github.com/Binary-Balance/seshat/pull/287),
resolving [#219](https://github.com/Binary-Balance/seshat/issues/219).

## Typecheck mutants

By default only original source is typechecked. Set `"typecheckMutants": true`
in a setup to run its `typecheck` command against each operator mutant before
any tests. A non-zero exit without an execution error gives the new
`compile-error` verdict: the mutant's tests do not run, and it is left out of
the score. Timeouts, cancellation and commands that fail to run stay
unresolved.

The setting requires `typecheck`, applies only to operator mutants and is
rejected with `--experimental-switching`. Extreme mutants are never
typechecked, because most body replacements would not match the declared
return type and checking them would hide pseudo-tested functions. On the
public examples, a type-valid mutant takes about 1.7 to 4.6 times as long, so
the setting is off by default. See
[typecheck mutants](../configuration.md#typecheck-mutants) and the
[measurements](../research/typecheck-mutants.md).

Reports add `mutation.compileErrors`, a per-operator `compileErrors` count and
the `compile-error` setup state. With the setting on, mutant typecheck jobs
count in `jobsAttempted`, and each worker's baseline typecheck appears under
`workerBaselines` with `phase: "typecheck"`. The readable per-operator line
says `job(s)` rather than `test job(s)`, since it can include typecheck jobs.
See the [report format](../report-format.md#mutation-assessment).
The change merged in [PR #288](https://github.com/Binary-Balance/seshat/pull/288),
resolving [#217](https://github.com/Binary-Balance/seshat/issues/217).

## Release packages and checks

The package set is `@binary-balance/seshat@0.17.0` with exact-version native
payloads for Linux x64, Linux ARM64, macOS x64, macOS ARM64 and Windows x64.
The [platform matrix](../platform-support.md) and runtime range are unchanged.
The report keeps schema version 1. With `typecheckMutants` off, verdicts on
code without string-literal arithmetic or declaration-only code are unchanged.

The published 0.16.0 audit is preserved unchanged as
[JSON](0.16.0-audit.json) and [Markdown](0.16.0-audit.md). The
[archive and notice audit](../research/release-notice-audit.md) records all six
exact archives built from head `217a29315bf2b3460bbcb940ca707394387ca58a` in
[PR #290](https://github.com/Binary-Balance/seshat/pull/290). All five native
package proofs, Windows runtime and latest-supported-Node checks passed.

The external dependency inventory, Rust 1.98.1 and runtime notice assets match
0.16.0. The notice bytes and SHA-256 are identical on all five targets and to
the previous release. No dependency or notice change is introduced.

The [retained native comparison](../research/mutant-validity-release-verdicts.md)
checks 838 report pairs against 0.16.0. All 3,333 shared outcomes, 527 source
assessment arrays, shared scores and completion states match. Every shared
per-operator row keeps its eligible, excluded and planned counts, so the new
exclusions remove no retained fixture mutant. No retained fixture sets
`typecheckMutants`, so `compileErrors` holds only its zero default. The new
[typecheck proof](https://github.com/Binary-Balance/seshat/actions/runs/42753276996/job/129621652420)
shows four type-invalid mutants as `compile-error` with the setting on, and a
type-valid control still killed. Fault-injection scheduling, receipt filename
numbering, Windows cancellation exit values, temporary proof folder names and
version text remain explicit in the evidence; none changes a verdict.

The
[five-host archive installation matrix](https://github.com/Binary-Balance/seshat/actions/runs/42760285166)
passed on every target at `5bc528b7d656944abcd394d872439344bba58fde`. Retained
artifact ZIP digests, staged archive hashes and installed native-binary
identities match the audit; all five public examples and worker parity pass.
