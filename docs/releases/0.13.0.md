# Seshat 0.13.0

Release preparation is tracked in
[#267](https://github.com/Binary-Balance/seshat/issues/267).

## Attribute import failures across supported Node 24

The Node import-failure observer now activates on stable Node `>=24.20.0 <25`,
matching the existing supported runtime range. Previously, only 24.20.0 and
24.21.0 activated it. On later supported patches, an application guard throwing
during import could leave a mutant unresolved despite attributable evidence.

Latest-node compatibility checks now require an active observer and an
attributed application import failure counted as a kill. Their summaries retain
the actual runtime, observer state and verdict. A later Node regression fails
that proof; restore a deliberate version pin and document the failing version
before shipping a change to the policy.

The attribution checks still require matching exception identity and a
parser-identified throw location in the mutated application. Setup failures,
ambiguous crashes and missing observation records remain unresolved. An active
runtime diagnostic alone does not prove that a crash is attributable.

The [range proof](../research/node-observer-range.md) retains all 26 scenarios
on Node 24.22.0 and 24.22.2. Eleven attributable application-import cases become
kills; the other fifteen verdicts are unchanged. The installed CLI proof keeps
all 85 scenarios, including readable output that withholds the score when load
evidence is missing.

Resolves [#228](https://github.com/Binary-Balance/seshat/issues/228), implemented
in [#264](https://github.com/Binary-Balance/seshat/pull/264).

## Separate collection phases

Collection now separates mutation planning, preparation, scheduling and summary,
and original checks, coverage attribution and mutation assessment. The helpers
and result structs remain private. Report fields, ordering, scoring, job counts,
cancellation and cleanup contracts are preserved.

The [before/after evidence](../research/collection-phases.md) covers the three
public runner examples and two-worker Node replacement and switching. It retains
the reports, job counts, timings and source hashes. These shared-host samples
make no performance claim.

Resolves [#226](https://github.com/Binary-Balance/seshat/issues/226), implemented
in [#265](https://github.com/Binary-Balance/seshat/pull/265).

## Check Rust formatting and Clippy in CI

Linux x64 package CI now checks formatting and denies default Clippy warnings
before running the Rust tests. The existing warnings are resolved with equivalent
conditions, simpler borrowing and a private test-hook type alias. Rust 1.98.1
remains the pinned toolchain; installed packages require no Rust toolchain.

Resolves [#224](https://github.com/Binary-Balance/seshat/issues/224), implemented
in [#266](https://github.com/Binary-Balance/seshat/pull/266).

## Release packages and checks

The package set is `@binary-balance/seshat@0.13.0` with exact-version native
payloads for Linux x64, Linux ARM64, macOS x64, macOS ARM64 and Windows x64.
The [platform support matrix](../platform-support.md) and report schema are
unchanged. No mutation operator or configuration option is added.

All three implementation PRs passed current-head fresh review and their
configured native checks before merging. The published 0.12.1 audit is preserved
unchanged as [JSON](0.12.1-audit.json) and [Markdown](0.12.1-audit.md).

The versioned native archive audit, release comparison, five-host local archive
installation, final review and publisher dry run are pending. Publication
requires approval of the prepared release under the
[npm publication checkpoint](../agents/delivery.md#npm-publication-checkpoint).
