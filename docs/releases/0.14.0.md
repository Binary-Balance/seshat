# Seshat 0.14.0

Release candidate. Preparation is tracked in
[#275](https://github.com/Binary-Balance/seshat/issues/275). Not published.

## Select test files for Jest/Expo and Node

Mutation jobs can select covering test files for verified Jest/Expo and
`node:test` setups, alongside the existing Vitest route. Original and worker
baselines still run the full command. Top-level `"testSelection": false`
restores full commands for every mutant.

Jest selection supports Jest 29.7.0 with jest-expo 57.0.5 or 57.0.6, the Seshat
Expo environment, one project, Babel coverage and verified babel-jest
transforms. Node selection supports stable Node `>=24.20.0 <25`, process
isolation and the supplied Istanbul collector recipe. Plain Jest remains
separate work in [#220](https://github.com/Binary-Balance/seshat/issues/220).
See [configuration](../configuration.md#mutation-execution) for exact command
options, supported workloads and fallback conditions.

Selection requires fresh per-file coverage and matching executed-test
identities. It preserves duplicate test names and each selected file's tests
and hooks. Counter resets, deletion, replacement or incomplete lifecycle
evidence disable attribution. Module-load calls, unsupported configurations
and ambiguous evidence use full commands. A completed selected job whose
executed tests cannot be confirmed gets one full retry; its first attempt and
both job counts remain in the report. Deadlines, cancellation and unsettled
cleanup cannot be replaced by a retry.

Both Node collector recipes instrument assessed query/fragment URL variants
under the original source path, then revoke selection for that run. These
imports retain honest source coverage and full test execution rather than
being mistaken for unused source files. Custom collectors must preserve the
managed imports and the documented instrumentation signal.

Node's synthetic passing wrappers for empty test files no longer count as
executed tests. A run containing no actual test bodies cannot pass. This is an
intentional assessment correction; existing attributable hook, timeout and
cleanup verdict policies remain unchanged.

The [selection evidence](../research/jest-node-selection.md) retains matched
full/selected verdicts, job counts and timings, plus reset/deletion, URL alias,
changed-workload, empty-run, timeout, cleanup and cancellation controls. Samples
describe those fixtures, not consumer performance. Source coverage determines
a conservative set of whole test files; cross-file state or order dependencies
remain a reason to disable selection.

Resolves [#186](https://github.com/Binary-Balance/seshat/issues/186), implemented
in [#274](https://github.com/Binary-Balance/seshat/pull/274).

## Record Seshat's own assessment baseline

Development tooling now records Rust coverage, complexity, advisory CRAP
scores and a mutation pilot, followed by targeted contract checks. Findings
were assessed for applicability; no broad architecture rewrite or hard quality
gate was introduced. A shared coverage observer was added only when Jest and
Node supplied two concrete consumers. The existing Rust selection/retry owner
remains in place.

See the [baseline](../research/rust-self-assessment.md) and
[follow-up](../research/rust-self-assessment-follow-up.md), delivered in
[#271](https://github.com/Binary-Balance/seshat/pull/271) and
[#273](https://github.com/Binary-Balance/seshat/pull/273).

## Release packages and checks

The package set is `@binary-balance/seshat@0.14.0` with exact-version native
payloads for Linux x64, Linux ARM64, macOS x64, macOS ARM64 and Windows x64.
The [platform matrix](../platform-support.md), runtime range and report schema
are unchanged. No mutation operator or configuration option is added.

The implementation passed fresh independent review and all ten configured
host checks before merging. The published 0.13.0 audit is preserved unchanged
as [JSON](0.13.0-audit.json) and [Markdown](0.13.0-audit.md).

Versioned native builds, the new archive/notice audit, five-host local archive
installation, final preparation review and the main-revision publisher dry run
remain release gates. Publication requires approval of the exact prepared
revision and six archives under the
[npm publication checkpoint](../agents/delivery.md#npm-publication-checkpoint).
