# Seshat 0.1.0-rc.1

Status: release candidate preparation. This note records the implemented CLI
behaviour and the agreed release boundaries. Final package manifests, artifact
identities, native package proofs and publication checks are still part of
release integration. No npm package or GitHub release is published.
Integration will add final artifact and evidence links once they exist.

## What the candidate does

Seshat is a native Rust CLI for TypeScript and TSX. It combines function-level
CRAP analysis with comparison-operator mutation testing. `check` runs both
assessments, `crap` runs coverage and CRAP analysis, and `mutate` runs original
typechecks, passing test baselines and mutation testing without collecting
coverage or calculating CRAP.

The declarative `seshat.json` configuration selects source files and named test
setups. Each mutant runs against every configured setup in a fresh test process
and an isolated execution copy. Source replacement is the default strategy;
`--experimental-switching` enables the separately reported switching
experiment. Full, source-mapped Istanbul JSON is required for coverage. The
[configuration guide](../configuration.md) documents the supported setup
shape and runner-specific requirements.

The tested runner families are Node's built-in test runner, Jest/Expo with
Babel coverage, and Vitest with Istanbul coverage. The recorded versions are
Node 24.20.0, Jest 29.7.0 with jest-expo 57.0.5 and Expo 57.0.20, and Vitest
5.0.0. Seshat writes readable terminal output by default. `--json` writes one
machine-readable report to stdout; progress remains on stderr. Quality
thresholds are optional.
CRAP uses statement coverage, and a mutation score counts killed and survived
mutants only when the run is complete. The [release scope](../release-scope.md)
defines the assessment rules.

## Candidate package and target support

The agreed npm layout is the exact version
`@binary-balance/seshat@0.1.0-rc.1`, with exact-version optional native payloads
`@binary-balance/seshat-linux-x64`, `@binary-balance/seshat-linux-arm64`,
`@binary-balance/seshat-darwin-x64`, `@binary-balance/seshat-darwin-arm64`, and
`@binary-balance/seshat-win32-x64`. A standalone native installation remains
part of the same candidate design. Consuming projects provide Node, their test
runner and their coverage tools; they do not need a Rust toolchain.

The supported native target set is Linux x64 and ARM64, macOS x64 and ARM64,
and Windows x64. The declared floors are Debian 11/glibc 2.31 for Linux x64,
Ubuntu 22.04/glibc 2.35 for Linux ARM64, macOS deployment target 15.0, and
native Windows Server 2022 build 20348. Windows ARM64 and Alpine Linux are
outside this release. Linux 6.8 is the oldest tested hosted kernel series; it
does not establish incompatibility below 6.8. These boundaries follow the
[release scope](../release-scope.md). Final rc.1 package bytes and native
installation evidence remain pending the packaging integration.

## JSON compatibility

Schema version 1 identifies the report contract; `toolVersion` identifies the
executable and can be `0.1.0-rc.1`. Within schema version 1, field names, JSON
types, nullability, score units, comparison rules and verdict meanings are
stable. Consumers must ignore unknown optional fields. Removing a stable field
or changing its meaning requires a new `schemaVersion`.

Error text, diagnostic text and runner receipts remain evidence rather than a
stable text protocol. The replacement strategy is the default. Switching and
its prepared-baseline fields are optional experimental data and must not be
treated as required by report consumers.

## Known limits

Source copies protect the checkout but do not sandbox test commands. Tests can
still access external files, services, databases and credentials, so commands
must be trusted. Seshat workers default to one. More workers require isolated
ports, files and databases, and the test runner's own concurrency must remain
bounded. Automatic per-test selection, persistent test-process reuse and
cross-run mutation-result caching are outside this release.

Missing or unreliable coverage is reported as unknown and makes the assessment
incomplete. Timeouts and execution errors remain unresolved; they do not count
as killed mutants. An incomplete run withholds the affected final score, and a
run with no mutants reports mutation as not applicable. A passing threshold or
complete run does not prove that the code is correct.

The runner integrations remain bounded to the tested configurations. Jest is
limited to Jest Circus, the default jest-expo environment and one project per
setup. Custom Jest runners, environments and projects are unverified. Vitest's
custom runner integration does not compose with another custom runner; browser
mode, other pools and broader versions are unverified. Line-only c8 coverage
does not meet the statement-coverage contract, and Vitest's V8 provider is
rejected when its function mapping is ambiguous. Broader mutation operators,
Playwright, HTML reports, dashboards and editor integrations are deferred.

## Historical performance attribution

Performance observations remain attributed to the issue 5 candidate revisions,
not to the unpublished rc.1 package. The `62bcddd2` records cover the original
installed release matrix and a matched Node Stryker comparison. The later
`d4b30a1` records cover installed replacement and switching runs. For the
worker-1 runs in the latter records, the complete-command medians were 1,844.678
ms for the Node workspace, 9,608.468 ms for Vitest TSX and 23,345.054 ms for
Jest/Expo TSX. Switching changed those medians by +6.42%, +10.17% and -5.56%;
worker-2 deltas were +8.07%, +24.75% and +2.33%.

Those are small Linux x64 fixture measurements. They are not a production
performance bound or a general recommendation for switching. The Stryker
comparison covers one matched Node mutation workload and excludes coverage,
CRAP and other phases. Keep these historical records separate from the final
rc.1 artifact, size and native verification evidence. See the [issue 5
performance audit](../release-performance-evidence.md).
