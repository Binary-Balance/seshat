# Seshat 0.15.0

Release candidate; not yet published. Release preparation and publication are
tracked in [#279](https://github.com/Binary-Balance/seshat/issues/279).

## Plain Jest with TypeScript and Babel coverage

Seshat now supports plain Jest 29.7.0 without Expo. The verified route uses
babel-jest 29.7.0, Babel's TypeScript preset and CommonJS transform, Babel
coverage, and either the default `jest-environment-node` or explicit
`jest-environment-jsdom` 29.7.0. The separate TypeScript command still checks
types; Babel removes them when running tests. Node `>=24.20.0 <25` remains the
supported runtime range.

The [plain Jest example](../../examples/jest/README.md) includes the locked
dependencies, Babel/Jest configuration and complete `seshat.json`. Keep
`--reporters={seshatReporter}` and `--env={seshatEnvironment}` in both the test
and coverage commands. Replacement and experimental switching are verified
with both environments. See the [compatibility guide](../runner-compatibility.md#plain-jest)
for the exact supported combinations.

Plain Jest runs the full configured command for every mutant. With default
test-file selection enabled, it reports `missing-test-files` and makes no
selected-file attempt. Top-level `"testSelection": false` also retains full
commands. The existing Vitest, Jest/Expo and Node selection routes are
unchanged; plain Jest support does not enable plain Jest selection.

Before each Jest test job, Seshat runs the same CLI with `--showConfig` to
resolve the original environment, then wraps it to collect execution evidence.
This adds a fresh configuration process per job; runner receipts record its
cost in `configDiscoveryMs`. Discovery is bounded to 15 seconds and 1 MiB of
output. Configuration files must be deterministic and safe to evaluate twice.
The retained fixture receipts measured 151.68–440.37 ms per discovery, with a
253.67 ms median on a shared Linux host. These timings describe that fixture,
not consumer performance.

The original resolved environment, environment options, other Jest CLI options
and project Babel setup remain in effect. Jest/Expo 57.0.5 and 57.0.6 support
is preserved. Discovery also waits for the actual Jest CLI when launched
through `npm test`; retained plain Jest and Expo npm-wrapper checks verify
baseline, coverage and mutation verdicts.

Only one project, the standard Jest runner and Circus 29.7.0, Babel coverage
and babel-jest transforms are supported. Custom environments/transforms,
per-file environment overrides, ts-jest, V8 coverage and other Jest versions
are outside this route. A file that bypasses the evidence wrapper leaves the
run incomplete. Tests must be deterministic: Seshat does not repeat baselines
to detect flaky tests or rerun kills to confirm them.

The [implementation evidence](../../outputs/plain-jest.md) records matching
replacement/switching measurements and verdicts, both npm-wrapper checks,
negative controls, job counts and phase timings. The implementation in
[PR #278](https://github.com/Binary-Balance/seshat/pull/278) passed fresh
independent review and all ten configured checks before merging, resolving
[#220](https://github.com/Binary-Balance/seshat/issues/220).

## Release packages and remaining checks

The candidate package set is `@binary-balance/seshat@0.15.0` with exact-version
native payloads for Linux x64, Linux ARM64, macOS x64, macOS ARM64 and Windows
x64. The [platform matrix](../platform-support.md), runtime range, mutation
operators, report schema and configuration options are unchanged.

The published 0.14.0 audit is preserved unchanged as
[JSON](0.14.0-audit.json) and [Markdown](0.14.0-audit.md). The current
[research audit](../research/release-notice-audit.md) still describes 0.14.0;
it is not candidate evidence for 0.15.0.

Release preparation still requires the exact candidate native archives and
notice audit, retained verdict comparison against 0.14.0, five-host local
archive installations, and the reviewed-revision publisher dry run. No new
0.15.0 archive audit, local-install matrix, publisher dry run or publication
result is claimed here. Publication requires separate approval of the
prepared release under the [npm publication checkpoint](../agents/delivery.md#npm-publication-checkpoint).
