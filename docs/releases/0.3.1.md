# Seshat 0.3.1

Fixes [#145](https://github.com/Binary-Balance/seshat/issues/145), a coverage
import regression introduced in 0.3.0.

## Coverage mapping

Logical conditions inside `if` statements and ternaries in object properties
now accept Istanbul ranges that include closing delimiters. The source syntax
bounds each accepted extension before the next executable expression.
The provider fixture passes with Vitest/Istanbul 5.0.0 and 5.0.3, alongside
Node/Istanbul and Jest/Expo.

Unreliable branch data leaves affected CRAP scores unknown while preserving
valid statement coverage and unaffected function scores. After all original
checks pass, mutations run even when coverage attribution is incomplete.
The combined assessment still exits `2` when CRAP is incomplete. Invalid
coverage files and failed original jobs still stop mutations.

Report schema version 1 remains in use. An `unknown` function row can now
retain numeric statement `coverage` when only its branch evidence is
unreliable. See the [report contract](../report-format.md).

## Release packages

The candidate package set is `@binary-balance/seshat@0.3.1` and its five
exact-version native payloads for Linux x64, Linux ARM64, macOS x64, macOS ARM64
and Windows x64. Dependency versions, Rust toolchain and runtime notice assets
remain as in 0.3.0. The [release audit](../research/release-notice-audit.md)
verifies all six archive identities, hashes and build provenance. Native
package checks passed on all five targets. The Windows runtime proof passed,
and the prepared Linux x64 archive passes the original reproduction.

The five-target local install matrix and publisher dry run remain pending.

Publication is pending approval of the prepared release.
