# Seshat 0.8.0

Published on 2026-10-20. Release preparation and publication are tracked in
[#187](https://github.com/Binary-Balance/seshat/issues/187).

## Statement removal mutations

The new `statement` mutation family is enabled by default. It replaces eligible
expression statements and bare returns with an empty statement. For example,
`log.push(value);` becomes `;`, and `if (stop) return;` becomes `if (stop) ;`.

Candidates belong directly to explicit synchronous, non-generator functions.
Constructors, module-level statements, declarations, directives, value-bearing
returns and statements containing `super()` are excluded. Nested functions
qualify independently. Source replacement and experimental switching preserve
statement boundaries and labels.

Select `["comparison", "logical", "arithmetic", "boolean"]` in
`mutationOperators` to retain the 0.7.0 operator scope. The broader default adds
test jobs and can change mutation scores. See the
[candidate rules](../configuration.md#mutation-operators) and
[semantic and cost evidence](../research/statement-mutations.md).
This completes [#164](https://github.com/Binary-Balance/seshat/issues/164).

## Vitest test-file selection

Verified Vitest Istanbul setups now run each mutant against the whole test
files that cover its source. Original and worker baselines still run the full
test command. Unsupported or ambiguous setups fall back to the full command,
including Jest and `node:test`. Set `"testSelection": false` to disable
selection.

Reports retain selected files, executed-test identities and fallback reasons.
Selection assumes test files run independently. Suites with cross-file state
or order dependencies should disable it. The
[selection proofs and limits](../research/test-selection.md) describe supported
setups and matched fixture results. This completes
[#181](https://github.com/Binary-Balance/seshat/issues/181).
Jest and `node:test` selection remains in
[#186](https://github.com/Binary-Balance/seshat/issues/186).

## Jest test-hook failures

A Jest mutant counts as killed when it has failed tests and every reported
error is proven to come from those tests' `beforeEach` or `afterEach` hooks.
Scheduling then continues. This includes Testing Library's automatic unmount
cleanup. Invalid or incomplete receipts, suite hooks, load failures and
infrastructure errors still stop scheduling. A Jest timeout no longer hides
unattributed errors in the same run; those errors stop scheduling too.

See the [verdict rules](../report-format.md#setup-jobs-and-evidence).
This completes [#182](https://github.com/Binary-Balance/seshat/issues/182).
