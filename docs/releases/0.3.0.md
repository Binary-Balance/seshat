# Seshat 0.3.0

CRAP now uses recorded Istanbul branch coverage. Statement coverage remains
available in the report. This changes the default directly; there is no
configuration switch. See [#130](https://github.com/Binary-Balance/seshat/issues/130).

Behaviour and platform limits not listed here remain as described in the
[0.2.0 release notes](0.2.0.md). Report schema version 1 is unchanged;
`toolVersion` is `0.3.0`.

## Branch coverage for CRAP

A function can run every statement while leaving decision outcomes untested.
At complexity 10, 100% statement coverage and 50% branch coverage now produce
CRAP 22.5 instead of 10. Existing `maxCrap` thresholds may therefore fail where
they previously passed.

Functions with no recorded branches use statement coverage. Missing or
unreliable branch maps leave CRAP unknown. Optional chaining and other decisions
can contribute to complexity without a provider branch counter; this measures
recorded outcomes, not every possible path. The
[provider measurements](../research/coverage-branches.md) cover Node/Istanbul,
Vitest/Istanbul and Jest/Expo, including default arguments and JSX.

## Report fields

Function rows add `branchCovered`, `branchTotal`, `branchCoverage` and
`coverageBasis`. Existing statement coverage fields keep their meanings.
`coverageBasis` identifies branch or statement coverage for a measured score;
it is null when no score is available. The terminal report shows branch counts.
See the [report format](../report-format.md).

## Release packages

The package set remains the entry package `@binary-balance/seshat@0.3.0` and
exact-version native payloads for Linux x64, Linux ARM64, macOS x64, macOS ARM64
and Windows x64. The five native package proofs and Windows runtime proof
passed. The six exact archives are recorded in the
[release audit](../research/release-notice-audit.md). Dependency versions, Rust
toolchain and runtime notice assets match 0.2.0.

Publication is pending approval of the prepared release.
