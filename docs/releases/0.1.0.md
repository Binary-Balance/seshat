# Seshat 0.1.0

Status: release preparation. This note records the implemented CLI behaviour,
package layout, supported target boundaries and known limits for version
0.1.0. Fresh native builds, six archive audit coordinates, host installation,
registry provenance and publication are separate release steps. This note does
not claim that those steps have passed.

The published 0.1.0-rc.1 bytes and their audit remain unchanged in the
[archived rc.1 audit](0.1.0-rc.1-audit.md) and its
[machine-readable record](0.1.0-rc.1-audit.json). The current installation
recipe is in the [README](../../README.md), the configuration guide describes
the setup contract, and the [report format](../report-format.md) defines the
schema version 1 JSON output.

## Implemented behaviour

Seshat is a native Rust CLI for TypeScript and TSX. It combines function-level
CRAP analysis with comparison-operator mutation testing. `check` runs both
assessments, `crap` runs fresh coverage and CRAP analysis, and `mutate` runs
the original typechecks and passing test baselines before mutation testing. The
`mutate` command does not collect coverage or calculate CRAP.

The declarative `seshat.json` configuration selects source files and named test
setups. Each mutant runs against every configured setup in a fresh test process
and an isolated execution copy. Source replacement is the default strategy.
`--experimental-switching` enables the separate switching experiment for
`check` and `mutate`; it is reported as experimental and is rejected by
`crap`. Coverage uses full, source-mapped Istanbul JSON.

The checked runner integrations are Node's built-in test runner, Jest/Expo with
Babel coverage, and Vitest with Istanbul coverage. The verified runtime floor
for the checked examples is Node 24.20.0. Seshat writes readable terminal
output by default. `--json` writes one report to stdout and progress notices to
stderr. `--no-progress` suppresses those notices. Optional quality thresholds
remain available through `thresholds.maxCrap` and
`thresholds.minMutationScore`.

Report schema version 1 remains the public contract. The `toolVersion` value
for this source is `0.1.0`; changing it does not change the schema. Consumers
must ignore unknown optional fields. Error and diagnostic text remain evidence
rather than a stable text protocol.

## Package layout and target boundaries

The release package set contains the entry package
`@binary-balance/seshat@0.1.0` and exact-version optional native payloads for
Linux x64, Linux ARM64, macOS x64, macOS ARM64 and Windows x64. The entry
package owns the `seshat` npm command and selects the matching native payload.
Each native package also supports direct standalone execution. The packaging
code writes the repository metadata required for trusted npm publication into
all six package manifests.

The target boundaries are Linux x64 on Debian 11 userspace with glibc 2.31,
Linux ARM64 on Ubuntu 22.04 with glibc 2.35, macOS 15.0 for both supported CPU
architectures, and Windows Server 2022 x64. Windows ARM64 and Alpine Linux
are outside this release. Linux 6.8 is the oldest tested hosted kernel series;
it is a test floor rather than a claim about older kernels. Consuming projects
provide Node, their test runner and their coverage tools. They do not need a
Rust toolchain.

## Installation

After publication, install the entry package at the exact `0.1.0` version from
the public npm registry. npm should select only the native payload matching the
host. The registry verifier checks the six-package dependency shape, the
selected native identity, the npm shim, the fixture result, and the plain
`seshat 0.1.0` CLI output. The verifier also asks npm 11.19.0 to
cryptographically verify `https://slsa.dev/provenance/v1` attestations for the
entry package and the selected native package.

During preparation, the same consumer route can use six local archives under
project-relative `vendor/seshat` paths. The two npm install commands add the
entry archive as a root dev dependency and the five native archives as root
optional dependencies. A final offline `npm ci --ignore-scripts` replays the
lockfile. The complete commands are in the [local installation recipe](../../README.md#install-a-local-010-archive).

## Known limits

Source copies protect the checkout but do not sandbox test commands. Tests can
still access external files, services, databases and credentials, so commands
must be trusted. Seshat workers default to one. More workers need isolated
ports, files and databases, and test-runner concurrency must remain bounded.
Automatic per-test selection, persistent test-process reuse and cross-run
mutation-result caching are outside this release.

Missing or unreliable coverage is reported as unknown and makes an assessment
incomplete. Timeouts and execution errors remain unresolved and do not count as
killed mutants. Incomplete runs withhold the affected final score. A run with
no mutants reports mutation as not applicable. A passing threshold or complete
run does not prove that the code is correct.

The runner integrations remain bounded to the tested configurations. Jest is
limited to Jest Circus, the default jest-expo environment and one project per
setup. Custom Jest runners, environments and projects are unverified. Vitest's
custom runner integration does not compose with another custom runner; browser
mode, other pools and broader versions are unverified. Line-only c8 coverage
does not meet the statement-coverage contract, and Vitest's V8 provider is
rejected when its function mapping is ambiguous. Broader mutation operators,
Playwright, HTML reports, dashboards and editor integrations are deferred.

The retained performance observations belong to earlier issue 5 candidate
revisions and are not measurements of the 0.1.0 package. They remain separate
historical evidence until a fresh release audit records any new measurements.
