# Seshat 0.4.0

Release preparation is tracked in
[#153](https://github.com/Binary-Balance/seshat/issues/153). Version 0.4.0 has
not been published.

## Pseudo-tested functions

`check` and `mutate` now replace each eligible function body once and run every
configured test setup. A replacement that survives with reliable positive
statement coverage marks the function as pseudo-tested. This means the tests
missed that body replacement, not that the function has no useful tests.
Per-function flags and counts are separate from comparison mutation scores and
have no quality threshold. See
[#131](https://github.com/Binary-Balance/seshat/issues/131).

Empty functions, constructors, accessors, generators, implicit scopes and
reliably zero-covered functions are skipped. Configured typechecks run only on
original source; test or build commands may still typecheck replacements.
Unresolved executions and unknown coverage leave the flag unknown. Extreme
mutation always uses source replacement, including when experimental comparison
switching is requested.

`mutate` now collects fresh coverage to skip unexecuted functions. It still does
not evaluate CRAP thresholds. Coverage attribution problems keep the assessment
incomplete, even when mutations resolve. Failed original checks and invalid
coverage files still stop mutations. The supported
[coverage routes and limits](../configuration.md#coverage) remain in
place.

## Type-safety findings

Selected source now reports explicit `any`, type assertions, double assertions,
non-null assertions and TypeScript suppression comments. Counts include function
signatures; nested functions have their own counts. Module-level escapes and
file-level `@ts-nocheck` comments remain visible in source findings.

Each setup reports effective compiler strictness through its installed
TypeScript, including inherited configuration, command-line overrides and
compiler defaults. Unsupported commands, missing configuration or unavailable
compiler metadata report `unknown` with an error. These findings do not change
assessment completeness or add quality thresholds.

This implements steps 1 and 2 of
[#134](https://github.com/Binary-Balance/seshat/issues/134). Inferred `any`
remains deferred in that issue. See the
[report contract](../report-format.md#type-safety-findings) and
[configuration limits](../configuration.md#type-safety-findings).

## Cognitive complexity

Function rows now include cognitive complexity beside cyclomatic complexity.
The optional `maxCognitiveComplexity` threshold applies in `check`, `crap` and
`mutate`. Cognitive scores do not use coverage, but the threshold is evaluated
only when the assessment is complete. Incomplete execution withholds its
result. CRAP continues to use cyclomatic complexity. See
[#132](https://github.com/Binary-Balance/seshat/issues/132).

Nested functions have separate scores. Recursion adds a penalty only for
established same-file identifier-call cycles with unambiguous, unwritten
bindings. Aliases, imports, member calls and cross-file cycles are not resolved;
a zero recursion increment does not establish the absence of recursion.
The [scoring rules and TypeScript choices](../cognitive-complexity.md) document
these limits and the deliberate differences from SonarSource's definition.

All report additions retain schema version 1. Consumers must ignore unknown
optional fields, as described in the [report contract](../report-format.md).

## Release packages and checks

The prepared package set is `@binary-balance/seshat@0.4.0` with exact-version
native payloads for Linux x64, Linux ARM64, macOS x64, macOS ARM64 and Windows
x64. Platform limits remain Linux glibc 2.31 for x64 and 2.35 for ARM64, macOS
15, and Windows Server 2022 x64. Alpine and desktop Windows are outside the
support claim. See the [platform support matrix](../platform-support.md).

The five native package proofs and Windows runtime proof pass. The
[0.4.0 archive and notice audit](../research/release-notice-audit.md) records
the six exact archives and their source trees. Its comparison with 0.3.1
confirms unchanged dependencies, Rust toolchain and notice bytes.

Five-target local installs, the publisher dry run and final review remain
pending. Publication requires approval of the prepared revision and six
packages under the
[npm publication checkpoint](../agents/delivery.md#npm-publication-checkpoint).
The published [0.3.1 audit](0.3.1-audit.md) is archived separately; it does not
provide 0.4.0 build or publication evidence.
