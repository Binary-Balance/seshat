# Seshat 0.16.0

Release candidate; not yet published. Release preparation and publication are
tracked in [#284](https://github.com/Binary-Balance/seshat/issues/284).

This release keeps assessment exclusions visible: partial coverage hints now
complete, and projects can declare mutants that cannot be killed. Each
exclusion appears in the report with its location and, for equivalent mutants,
its reason.

## Partial coverage hints

Istanbul `/* istanbul ignore next */`, `ignore if` and `ignore else` hints
inside a function no longer leave that function unknown and the run
incomplete. Seshat checks each hint's exact AST target and each setup's
retained coverage counters before merging setups. The containing function is
reported `partially-suppressed`, with coverage of the code that remains and no
CRAP score, so a partial exclusion can never pass `maxCrap`. Static findings
and mutation jobs for that function are kept. Whole-function and whole-file
suppression, shipped in 0.12.0, is unchanged.

Unsupported hint placements and missing, deleted or contradictory retained
counters still leave the function unknown and the run incomplete. See
[coverage suppression hints](../configuration.md#coverage-suppression-hints).
The [implementation evidence](../../outputs/partial-coverage-suppression.md)
covers Node/Istanbul, Vitest/Istanbul, plain Jest and Jest/Expo. The change
merged in [PR #282](https://github.com/Binary-Balance/seshat/pull/282),
resolving [#215](https://github.com/Binary-Balance/seshat/issues/215).

## Equivalent mutant declarations

Some mutants cannot be killed: the change behaves like the original for every
value that can reach it. A block comment directly before the mutation token
declares one replacement equivalent:

```ts
const confidence = row.confidence
  /* seshat-equivalent ?? -> ||: value is 1–5 or null */ ?? undefined;
```

Declared mutants still run in both mutation strategies, including where
coverage would otherwise skip them. If the tests pass, the mutant is
`equivalent` and left out of the mutation score. If they kill it, it counts as
killed and the declaration is reported `stale`. Timeouts, execution errors and
other unresolved outcomes keep their usual verdicts. When every mutant is
declared equivalent, the score is `null` and `minMutationScore` does not apply.

Declarations bind to one site and one named replacement. Adjacent declarations
can cover several replacements at one site. A malformed, duplicate or unmatched
declaration is an input error, checked before any job runs. A valid declaration
for a disabled operator family is reported `inactive`. Seshat checks where a
declaration points, not whether the claim is true.

Reports add `equivalent` and `staleDeclarations` totals, a per-operator
`equivalent` count, each source's `equivalentDeclarations` and each mutation
outcome's `equivalence`. A declared mutant that coverage would have skipped
records the selection reason `declared-equivalent`. See
[equivalent mutant declarations](../configuration.md#equivalent-mutant-declarations)
and the [report format](../report-format.md#equivalent-mutant-declarations).
The change merged in [PR #283](https://github.com/Binary-Balance/seshat/pull/283),
resolving [#233](https://github.com/Binary-Balance/seshat/issues/233).

## Release packages and remaining checks

The candidate package set is `@binary-balance/seshat@0.16.0` with exact-version
native payloads for Linux x64, Linux ARM64, macOS x64, macOS ARM64 and Windows
x64. The [platform matrix](../platform-support.md), runtime range and mutation
operators are unchanged. The report keeps schema version 1; its additions are
the `partially-suppressed` function status, the `equivalent` verdict and the
fields above. Undeclared verdicts are unchanged.

The published 0.15.0 audit is preserved unchanged as
[JSON](0.15.0-audit.json) and [Markdown](0.15.0-audit.md). The
[archive and notice audit](../research/release-notice-audit.md) records all six
exact archives built from head `8c4c97c424872264ed0cbe4d6f5531096a31da1a` in
[PR #285](https://github.com/Binary-Balance/seshat/pull/285). All five native
package proofs, Windows runtime and latest-supported-Node checks passed.

The external dependency inventory, Rust 1.98.1 and runtime notice assets match
0.15.0. The notice bytes and SHA-256 are identical on all five targets and to
the previous release. No dependency or notice change is introduced.

The [retained native comparison](../research/exclusions-release-verdicts.md)
checks 838 report pairs against 0.15.0. All 3,333 shared outcomes, 527 source
assessment arrays, shared scores and completion states match. No retained
fixture declares an equivalent mutant, so the new report fields hold only
their empty defaults. Fault-injection scheduling, receipt filename numbering,
Windows cancellation exit values, temporary proof folder names and version
text remain explicit in the evidence; none changes a verdict.

Release preparation still requires five-host local archive installations, and
the reviewed-revision publisher dry run after merging. No publisher dry run or publication result is claimed here.
Publication requires separate approval of the prepared release under the
[npm publication checkpoint](../agents/delivery.md#npm-publication-checkpoint).
