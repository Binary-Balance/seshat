# Seshat 0.7.0

Release preparation and publication are tracked in
[#177](https://github.com/Binary-Balance/seshat/issues/177). Publication is pending.

## Boolean and negation mutations

The new `boolean` family is enabled by default. It flips runtime `true` and
`false` literals and removes prefix `!`, including its boolean conversion.
For example, `!7` becomes `(7)`. Type-level literals, ambient declarations,
non-runtime keys and TypeScript postfix non-null assertions are excluded.

Select `["comparison", "logical", "arithmetic"]` in `mutationOperators` to
retain the 0.6.0 operator scope. The broader default adds test jobs and can
change mutation scores. Each new mutant adds one test job per applicable setup.
The [semantic and cost evidence](../research/boolean-mutations.md) records the
fixed examples, hand-checked equivalent candidates and matched measurements.

Source replacement and experimental switching preserve statement boundaries
when semicolons are omitted. Switching explicitly rejects reference-sensitive
negation removal that its inline arms cannot preserve. See the
[configuration guide](../configuration.md#mutation-operators) for the exact
forms and existing experimental limits. This completes
[#163](https://github.com/Binary-Balance/seshat/issues/163).

## Type-safety thresholds

Optional `maxInferredAny` and `maxTypeEscapes` limits apply in `crap`, `check`
and `mutate`. Inferred limits apply separately to each setup. Syntax escapes
count once across selected source; type assertions and non-null assertions do
not contribute to that limit.

Unknown required inferred evidence makes the configured check incomplete and
exits 2 while retaining valid assessment results. Findings remain non-blocking
when the limits are disabled. These are fixed count limits with no stored
baseline or automatic tightening. See the
[threshold rules](../configuration.md#quality-thresholds) and
[report fields](../report-format.md). This completes
[#174](https://github.com/Binary-Balance/seshat/issues/174).
